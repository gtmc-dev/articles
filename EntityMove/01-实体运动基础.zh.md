任何能在 Minecraft 中"动"的东西——玩家、生物、掉落物、TNT、箭矢——都是一个**实体**（Entity）。它们共享一套统一的运动描述体系。

## 核心运动属性

所有可运动实体都具备以下属性。理解它们的准确定义是使用后续公式的前提：

| 属性 | 含义 | 与现实物理的差异 |
|---|---|---|
| **碰撞箱**（AABB） | 标记实体占用空间的长方体，各面垂直于坐标轴 | 不会随实体朝向旋转，俯视图始终是正方形 |
| **坐标** | 实体位置的基准点，通常位于碰撞箱底面中心 | 坐标变化不一定由速度决定（可被传送） |
| **Motion** | 存储速度及其运算中间量的三维向量 | **不等于速度**——见下方详细说明 |
| **速度** | 实体在一定时间内的实际坐标变化量 | 是运动的结果，不是运动的决定量 |
| **眼部坐标** | 某些计算用的参考点，Y 轴比坐标高出一定比例 | 通常为实体高度的 0.85 倍，箭矢为 0.13 |
| **俯仰角**（pitch） | 竖直朝向，-90°~90° | 水平为 0°，向上为负，向下为正 |
| **偏航角**（yaw） | 水平朝向，-180°~180° | 正南为 0°，顺时针为正 |
| **空气阻力系数** | 自由运动时每 gt 速度衰减的比例 | 连续物理中 $dv/dt = -fv$；MC 中是 $M_{n+1} = M_n(1-f)$ |

### Motion 与速度的本质区别

Motion 不是速度。这个事实是整个实体运动理论中最容易被误解的一点。

**Motion 是输入**：每次加速和阻力作用时，Motion 被修改。在移动时，Motion 被用作该 gt 的位移量。

**速度是输出**：速度是实际坐标变化量除以时间。由于碰撞、方块交互和顺序效应，速度可能不等于 Motion。

一个极端例子：堆叠的矿车被充能铁轨加速时，Motion 以指数速度增长（趋近无穷大），但实际单轴速度被硬限制在 0.4 m/gt。Motion 可以爆炸，但速度不会。

日常使用中，将 Motion 理解为"速度"问题不大。但在精确计算中（特别是涉及多个运算阶段的场景），区分两者至关重要。

## 六类基本运算

每个可运动实体在每 gt 中经历以下运算中的一部分或全部。它们的顺序决定了实体的运动模式：

| 缩写 | 含义 | 运算内容 |
|---|---|---|
| **G**（Gravity） | 重力作用 | 在 Y 轴 Motion 上减去固定的重力加速度（通常为 0.08 m/gt²） |
| **D**（Drag） | 阻力作用 | 将指定轴上的 Motion 乘以速度乘数 $k = 1 - f$ |
| **C**（Controlled Acceleration） | 自身加速 | AI、玩家输入或充能铁轨等驱动的主动加速 |
| **F**（Fluid Acceleration） | 流体加速 | 水、岩浆等流体的推动或阻力 |
| **Dc**（Displacement Calculation） | 位移确定 | 根据 Motion 计算本 gt 的位移趋势 |
| **Pu**（Position & AABB Update） | 坐标及碰撞箱更新 | 实际移动碰撞箱和坐标 |

其中，移动（位移确定 + 坐标更新）通常被合并为 **M**（Movement）。

### 阻力：为什么是乘法

在连续牛顿力学中，阻力被描述为微分方程：

$$\frac{dv}{dt} = a - fv$$

但在 Minecraft 中，$dt$ 不能小于 1 gt。Mojang 的实现是每 gt 执行一次：

$$M_{n+1} = M_n(1 - f \cdot t_0)$$

记 $k = 1 - f \cdot t_0$（$t_0 = 1\text{gt}$），则：

$$M_{n+1} = M_n \cdot k$$

**阻力的本质是 Motion 每 gt 乘以一个常数 k**。这个常数被称为**速度乘数**。

与连续物理的指数衰减 $v = v_0 e^{-ft}$ 不同，Minecraft 中的实际衰减是几何级数 $M_n = M_0 \cdot k^n$——当 k < 1 时，Motion 以 k 的幂次衰减。

### 分类：按运算顺序

根据 G、D、M 的顺序，实体可分为六大类（以及它们因某些分量缺失而派生的子类）：

| 类型 | 顺序 | 代表实体 |
|---|---|---|
| **MDG** | 移动 → 阻力 → 重力 | 玩家、大部分生物 |
| **DMG** | 阻力 → 移动 → 重力 | TNT、下落的方块 |
| **DGM** | 阻力 → 重力 → 移动 | 物品、经验球 |
| **MGD** | 移动 → 重力 → 阻力 | （极少） |
| **GMD** | 重力 → 移动 → 阻力 | 部分弹射物 |
| **GDM** | 重力 → 阻力 → 移动 | （极少） |
| **DM** | 阻力 → 移动 | 无重力实体（如 TNT 在水中） |

同一实体在同一状态下（如是否在水中）运算顺序不变。具体可参考 lovexyn0827 原文附录 A。

## 实体运算顺序

原版 Minecraft 服务端是单线程的。同一 gt 内，所有实体的运算按以下规则确定顺序：

1. **根实体**（没有骑乘任何实体的实体）最先运算。
2. 所有根实体中，**最早被加载**到所在维度的实体先运算。
3. 任意实体若有骑乘者，骑乘者**紧随其后**运算。
4. 一组同位实体（直接骑乘同一实体的实体）中，**最早开始骑乘**的实体先运算。

简而言之：**加载早的先算，骑乘的跟着算，同位按骑乘先后算**。

这些规律的源码依据在 `ServerWorld.tick()`、`ServerWorld.tickEntity()` 和 `ServerWorld.tickPassenger()` 中。

## 小结

- Motion 是运动的决定量（输入），速度是运动的结果量（输出）；两者在大多数情况下接近但不相等。
- 加速度的本质是加法（`Motion += a`），阻力的本质是乘法（`Motion *= k`），其中 $k = 1 - f$。
- 每 gt 实体经历 G（重力）、D（阻力）、M（移动）及其他运算；它们的顺序决定了实体的 MDG/DMG 等类型。
- 实体运算顺序由加载时间、骑乘关系和骑乘先后决定——单线程、确定性的顺序。
