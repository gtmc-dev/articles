读完[上一篇](./加载票系统中的类型.zh.md)后，你已经认识了 Ticket、TicketType、Level、LevelType、ChunkHolder 和 ChunkStatus 这些名词。本篇负责把这些名词连成一条完整的流程线：一张票从哪里来，如何让区块保持加载，区块离开加载后发生了什么。

## 从现象出发

先看几个你能在游戏中直接观察到的现象：

- **离开后机器停止**：你在出生点旁建了一台刷石机，走远后它停了。走回去时，出水口重新开始流水。但你走得更远再回来，它可能连状态都重置了。
- **传送门延迟**：穿过下界传送门后，你看到了加载地形画面。如果你快速跑开，远处的地形可能还没加载完毕。
- **`/forceload` 让区块永远不卸载**：使用这个指令后，无论你离得多远，那个区块的机器都在运行。
- **渲染距离和模拟距离不同**：服务器设置中有两个独立选项："视距"和"模拟距离"。把模拟距离调低后，远处地形还看得见，但红石装置已经停了。

这些现象的背后，是同一套系统在运作：**加载票系统**。

## 整体架构

`ChunkTicketManager` 是这套系统的核心。它的整体结构如下：

```
                         ┌─────────────────────────┐
                         │   ChunkTicketManager     │
                         │                          │
 ticketsByPosition ──────┤  (SortedArraySet 每区块)  │
                         │                          │
 distanceFromTicketTracker ──┤  TicketDistanceLevelPropagator
 distanceFromNearestPlayerTracker ──┤  DistanceFromNearestPlayerTracker
 simulationDistanceTracker ──┤  SimulationDistanceLevelPropagator
 nearbyChunkTicketUpdater ──┤  NearbyChunkTicketUpdater
                         │                          │
                         │  ↓ setLevel 回调         │
                         │  ThreadedAnvilChunkStorage│
                         │    → ChunkHolder.setLevel │
                         │    → ChunkHolder.tick     │
                         └─────────────────────────┘
```

四个追踪器各自负责一种 level 的传播，最终汇集到 `ChunkHolder` 的 `tick()` 方法中，决定区块该做什么。

## Ticket 的生命周期

### 1. 添加 Ticket

一个 Ticket 被添加到系统时，调用路径是：

```java
// ChunkTicketManager.java
public <T> void addTicket(ChunkTicketType<T> type, ChunkPos pos, int radius, T argument) {
    // level = 33（FULL）- radius
    ChunkTicket<T> chunkTicket = new ChunkTicket<>(type,
        ChunkLevels.getLevelFromType(ChunkLevelType.FULL) - radius, argument);
    long l = pos.toLong();
    this.addTicket(l, chunkTicket);
    this.simulationDistanceTracker.add(l, chunkTicket);  // 同步写入模拟距离追踪器
}
```

`addTicket(l, chunkTicket)` 内部：

```java
void addTicket(long position, ChunkTicket<?> ticket) {
    SortedArraySet<ChunkTicket<?>> sortedArraySet = this.getTicketSet(position);
    int i = getLevel(sortedArraySet);                    // 旧的最小 level
    ChunkTicket<?> chunkTicket = sortedArraySet.addAndGet(ticket);
    chunkTicket.setTickCreated(this.age);                // 记录创建时间
    if (ticket.getLevel() < i) {                         // 新票 level 更低 → 通知追踪器
        this.distanceFromTicketTracker.updateLevel(position, ticket.getLevel(), true);
    }
}
```

`SortedArraySet` 按 level 升序排列。`getLevel` 取集合中第一个元素（最小的 level）。如果同一个区块有多张票，只有**最低 level**（即最"强"的加载）的那张生效。

### 2. Level 的传播

一张票直接添加到中心区块后，周围区块如何获得自己的 level？

`TicketDistanceLevelPropagator` 继承 `ChunkPosDistanceLevelPropagator`，后者实现了经典的 level 传播算法：

```java
// ChunkPosDistanceLevelPropagator.java
// propagateLevel：从源点向 8 个邻居传播，每步 level+1
protected void propagateLevel(long id, int level, boolean decrease) {
    ChunkPos chunkPos = new ChunkPos(id);
    for (int k = -1; k <= 1; k++) {
        for (int l = -1; l <= 1; l++) {
            long m = ChunkPos.toLong(chunkPos.x + k, chunkPos.z + l);
            if (m != id) {
                this.propagateLevel(id, m, level, decrease);
            }
        }
    }
}

// recalculateLevel：每个区块取 8 个邻居的最小 (level+1)
protected int recalculateLevel(long id, long excludedId, int maxLevel) {
    int i = maxLevel;
    for (int l = -1; l <= 1; l++) {
        for (int m = -1; m <= 1; m++) {
            long n = ChunkPos.toLong(j + l, k + m);
            int o = this.getPropagatedLevel(n, id, this.getLevel(n));
            if (i > o) i = o;
            if (i == 0) return i;
        }
    }
    return i;
}

protected int getPropagatedLevel(long sourceId, long targetId, int level) {
    return this.getInitialLevel(targetId);  // level 传播：源点中心值，邻居 +1
}
```

**传播规则**：以票所在区块为中心，每向外走一个区块（包括对角线），`level + 1`。最终每个区块取所有传播路径中的最小值。

例如，一张 `radius=2`（level=31）的玩家票加在 `(0,0)`：

```
 35  34  33  34  35
 34  33  32  33  34
 33  32 [31] 32  33    ← (0,0) 中心 = 31
 34  33  32  33  34
 35  34  33  34  35
```

### 3. 通知 ChunkHolder

当传播计算出某个区块的 level 发生变化时，`TicketDistanceLevelPropagator.setLevel` 被调用：

```java
// ChunkTicketManager.TicketDistanceLevelPropagator
protected void setLevel(long id, int level) {
    ChunkHolder chunkHolder = ChunkTicketManager.this.getChunkHolder(id);
    int i = chunkHolder == null ? UNLOADED : chunkHolder.getLevel();
    if (i != level) {
        chunkHolder = ChunkTicketManager.this.setLevel(id, level, chunkHolder, i);
        if (chunkHolder != null) {
            ChunkTicketManager.this.chunkHolders.add(chunkHolder);  // 加入待处理集合
        }
    }
}
```

`setLevel` 由 `ThreadedAnvilChunkStorage` 实现，负责创建或更新 `ChunkHolder`：

```java
// ThreadedAnvilChunkStorage.java
ChunkHolder setLevel(long pos, int level, @Nullable ChunkHolder holder, int i) {
    if (!ChunkLevels.isAccessible(i) && !ChunkLevels.isAccessible(level)) {
        return holder;  // 都不可访问 → 不处理
    }
    if (holder != null) {
        holder.setLevel(level);  // 已有 holder → 更新 level
    }
    if (holder != null) {
        if (!ChunkLevels.isAccessible(level)) {
            this.unloadedChunks.add(pos);  // 标记为可卸载
        }
    }
    if (ChunkLevels.isAccessible(level) && holder == null) {
        // 首次进入可访问范围 → 复用或新建 ChunkHolder
        holder = this.chunksToUnload.remove(pos);
        if (holder != null) {
            holder.setLevel(level);       // 复用即将卸载的 holder
        } else {
            holder = new ChunkHolder(new ChunkPos(pos), level, this.world,
                this.lightingProvider, this.chunkTaskPrioritySystem, this);
        }
        this.currentChunkHolders.put(pos, holder);
    }
    return holder;
}
```

当一个区块的 level 首次进入可访问范围（≤ `INACCESSIBLE`）时，系统为它创建 `ChunkHolder`；当 level 重新超出可访问范围时，`ChunkHolder` 进入卸载队列。

### 4. ChunkHolder.tick：响应等级变化

所有 level 发生变化的 `ChunkHolder` 被收集到 `chunkHolders` 集合中。`ChunkTicketManager.tick()` 每 tick 遍历这个集合，调用每个 holder 的 `tick()`：

```java
// ChunkTicketManager.java
public boolean tick(ThreadedAnvilChunkStorage chunkStorage) {
    this.distanceFromNearestPlayerTracker.updateLevels();
    this.simulationDistanceTracker.updateLevels();
    this.nearbyChunkTicketUpdater.updateLevels();
    this.distanceFromTicketTracker.update(Integer.MAX_VALUE);
    // ...
    if (!this.chunkHolders.isEmpty()) {
        this.chunkHolders.forEach(holder -> holder.tick(chunkStorage, this.mainThreadExecutor));
        this.chunkHolders.clear();
    }
}
```

`ChunkHolder.tick()` 对比上一次 tick 的 level 类型与当前 level 类型，决定该提升、降级还是维持：

```java
// ChunkHolder.java
protected void tick(ThreadedAnvilChunkStorage chunkStorage, Executor executor) {
    ChunkLevelType chunkLevelType = ChunkLevels.getType(this.lastTickLevel);   // 旧
    ChunkLevelType chunkLevelType2 = ChunkLevels.getType(this.level);          // 新

    // [降级] 旧等级可访问、新等级不可访问 → 清空未来状态
    boolean bl = ChunkLevels.isAccessible(this.lastTickLevel);
    boolean bl2 = ChunkLevels.isAccessible(this.level);
    if (bl) {
        for (int i = bl2 ? chunkStatus2.getIndex() + 1 : 0; i <= chunkStatus.getIndex(); i++) {
            this.futuresByStatus.set(i, CompletableFuture.completedFuture(either));
        }
    }

    // [升级] 进入 FULL → 使区块可访问（加载进内存）
    boolean bl3 = chunkLevelType.isAfter(ChunkLevelType.FULL);
    boolean bl4 = chunkLevelType2.isAfter(ChunkLevelType.FULL);
    if (!bl3 && bl4) {
        this.accessibleFuture = chunkStorage.makeChunkAccessible(this);
        this.combineSavingFuture(this.accessibleFuture, "full");
    }
    // [降级] 退出 FULL → complete UNLOADED
    if (bl3 && !bl4) {
        this.accessibleFuture.complete(UNLOADED_WORLD_CHUNK);
        this.accessibleFuture = UNLOADED_WORLD_CHUNK_FUTURE;
    }

    // [升级] 进入 BLOCK_TICKING → 使区块 participate in ticking
    boolean bl5 = chunkLevelType.isAfter(ChunkLevelType.BLOCK_TICKING);
    boolean bl6 = chunkLevelType2.isAfter(ChunkLevelType.BLOCK_TICKING);
    if (!bl5 && bl6) {
        this.tickingFuture = chunkStorage.makeChunkTickable(this);
        this.combineSavingFuture(this.tickingFuture, "ticking");
    }
    if (bl5 && !bl6) {
        this.tickingFuture.complete(UNLOADED_WORLD_CHUNK);
        this.tickingFuture = UNLOADED_WORLD_CHUNK_FUTURE;
    }

    // [升级] 进入 ENTITY_TICKING → 使实体开始运算
    boolean bl7 = chunkLevelType.isAfter(ChunkLevelType.ENTITY_TICKING);
    boolean bl8 = chunkLevelType2.isAfter(ChunkLevelType.ENTITY_TICKING);
    if (!bl7 && bl8) {
        this.entityTickingFuture = chunkStorage.makeChunkEntitiesTickable(this);
        this.combineSavingFuture(this.entityTickingFuture, "entity ticking");
    }
    if (bl7 && !bl8) {
        this.entityTickingFuture.complete(UNLOADED_WORLD_CHUNK);
        this.entityTickingFuture = UNLOADED_WORLD_CHUNK_FUTURE;
    }

    this.lastTickLevel = this.level;
}
```

这里有三个分界点，对应三种 `CompletableFuture`：

| Future | 触发条件 | 对应行为 |
|---|---|---|
| `accessibleFuture` | 进入 FULL（level ≤ 33） | 区块数据可供读取、方块状态可查询 |
| `tickingFuture` | 进入 BLOCK_TICKING（level ≤ 32） | 方块实体运算、红石运算、随机刻 |
| `entityTickingFuture` | 进入 ENTITY_TICKING（level ≤ 31） | 实体 AI、移动、刷怪 |

当等级降级时，对应的 future 被 `complete(UNLOADED_WORLD_CHUNK)`，表示该层级运算已停止。

### 5. Ticket 过期与移除

添加 Ticket 时记录了 `age`。每 tick，`purge()` 方法遍历所有 ticket，清除已过期的：

```java
// ChunkTicketManager.java
protected void purge() {
    this.age++;
    // 遍历 ticketsByPosition，移除 isExpired 的 ticket
    while (iterator.hasNext()) {
        ChunkTicket<?> chunkTicket = iterator.next();
        if (chunkTicket.isExpired(this.age)) {
            iterator.remove();
            this.simulationDistanceTracker.remove(entry.getLongKey(), chunkTicket);
        }
    }
    // ticket 集为空 → 从 ticketsByPosition 移除
    // 有 ticket 被移除 → 通知 distanceFromTicketTracker 更新 level
}
```

不同类型的 ticket 有不同的过期时间：
- `POST_TELEPORT`：5gt 后过期
- `UNKNOWN`：1gt 后过期
- `PORTAL`：300gt（15秒）后过期
- `PLAYER`、`FORCED`、`START`、`DRAGON`：不休眠——只要源还在，票就一直在

### 6. 区块保存与卸载

移除 Ticket 后，`distanceFromTicketTracker` 对该区块的 level 上升。当 level 超过 `INACCESSIBLE` 时，`ThreadedAnvilChunkStorage` 将其加入 `unloadedChunks` 队列。系统会在合适时机保存并卸载它：

```java
// ThreadedAnvilChunkStorage.java - save 方法（简化）
private boolean save(Chunk chunk) {
    if (!chunk.needsSaving()) return false;
    chunk.setNeedsSaving(false);
    // 序列化并写入文件
    // ...
}
```

只有 `needsSaving` 为 `true` 的区块才会被写回磁盘。这是 `WorldChunk.setBlockState` 中将 `needsSaving` 设为 `true` 的原因——它确保了被修改过的区块在卸载前一定会被保存。

## 玩家加载：视距与模拟距离

玩家是游戏中最常见的 Ticket 来源。这个流程涉及 `DistanceFromNearestPlayerTracker` 和 `NearbyChunkTicketUpdater`。

### 玩家进入/离开区块

当玩家所在的区块发生变化时：

```java
// ChunkTicketManager.java
public void handleChunkEnter(ChunkSectionPos pos, ServerPlayerEntity player) {
    ChunkPos chunkPos = pos.toChunkPos();
    long l = chunkPos.toLong();
    // 1. 记录玩家位于哪个区块
    this.playersByChunkPos.computeIfAbsent(l, ...).add(player);
    // 2. 通知距离追踪器：这个区块距离玩家 = 0
    this.distanceFromNearestPlayerTracker.updateLevel(l, 0, true);
    // 3. 通知 nearbyChunkTicketUpdater
    this.nearbyChunkTicketUpdater.updateLevel(l, 0, true);
    // 4. 添加模拟距离票
    this.simulationDistanceTracker.add(ChunkTicketType.PLAYER, chunkPos,
        this.getPlayerSimulationLevel(), chunkPos);
}
```

### 两种距离、两级传播

`DistanceFromNearestPlayerTracker` 对应**视距（view distance）**，控制哪些区块的数据会被发送给客户端。它使用 `ChunkPosDistanceLevelPropagator` 将玩家所在区块的 level 沿 8 方向传播。

`NearbyChunkTicketUpdater` 继承自前者，额外控制**哪些区块会创建 PLAYER 类型 Ticket**。当区块与玩家的距离 ≤ `watchDistance` 时，它为该区块添加一张 `NEARBY_PLAYER_TICKET_LEVEL`（= `ENTITY_TICKING`，31）级别的票：

```java
// NearbyChunkTicketUpdater
private void updateTicket(long pos, int distance, boolean oldWithinViewDistance, boolean withinViewDistance) {
    if (oldWithinViewDistance != withinViewDistance) {
        ChunkTicket<?> chunkTicket = new ChunkTicket<>(ChunkTicketType.PLAYER,
            NEARBY_PLAYER_TICKET_LEVEL, new ChunkPos(pos));
        if (withinViewDistance) {
            ChunkTicketManager.this.addTicket(pos, chunkTicket);
        } else {
            ChunkTicketManager.this.removeTicket(pos, chunkTicket);
        }
    }
}
```

这张票的 level 固定为 31（`ENTITY_TICKING`），它通过 `TicketDistanceLevelPropagator` 向外传播，确保玩家视距范围内的所有区块都有合适的加载等级。

### 模拟距离：又一个独立的传播层

视距控制"是否发送区块数据给客户端"，但服务器是否需要**完整运算**这些区块（红石、实体），则由模拟距离控制。

`SimulationDistanceLevelPropagator` 是一个完全独立的 level 传播器。它的初始 level 由 `getPlayerSimulationLevel()` 计算：

```java
// ChunkTicketManager.java
private int getPlayerSimulationLevel() {
    return Math.max(0,
        ChunkLevels.getLevelFromType(ChunkLevelType.ENTITY_TICKING) - this.simulationDistance);
    // = Math.max(0, 31 - simulationDistance)
}
```

当服务器设置 `simulationDistance = 10`，玩家所在区块的模拟 level = `31 - 10 = 21`（远低于 31，即比 `ENTITY_TICKING` 更强）。这个 level 同样向外传播，每格 +1。

`shouldTickEntities` 和 `shouldTickBlocks` 通过查询 `simulationDistanceTracker` 判断：

```java
public boolean shouldTickEntities(long chunkPos) {
    return ChunkLevels.shouldTickEntities(this.simulationDistanceTracker.getLevel(chunkPos));
}
```

这解释了**渲染距离 ≠ 模拟距离**：渲染距离内的所有区块都会发送数据给客户端（你能看见），但只有模拟距离内的区块才会执行方块和实体运算（它们真的在"运行"）。

## 完整案例追踪

### 案例 1：玩家走远了，机器为什么停？

1. 玩家在 `(0,0)` 区块运行一台刷石机。`NearbyChunkTicketUpdater` 为该区块添加 level=31 的 PLAYER ticket。
2. 这张 ticket 在 `TicketDistanceLevelPropagator` 中传播，使该区块的 `ChunkHolder.level = 31`，`ENTITY_TICKING`。
3. 玩家走到远处，新版块进入视距。`handleChunkLeave` 移除旧区块的玩家记录。
4. `NearbyChunkTicketUpdater` 检测到距离超出 `watchDistance`，移除 PLAYER ticket。
5. `TicketDistanceLevelPropagator` 重新计算，该区块 level 上升。如果没有任何其他 ticket，level 最终变为 `INACCESSIBLE + 1`。
6. `ThreadedAnvilChunkStorage.setLevel` 将 `ChunkHolder` 加入卸载队列。
7. 如果区块被修改过（`needsSaving = true`），保存到磁盘。
8. `ChunkHolder` 的三个 future 被 complete（UNLOADED），系统卸载该区块。

如果玩家在步骤 7 之前走回来，`ChunkHolder` 的 level 重新降回 31 或以下——机器恢复运行。但如果已经完成了卸载步骤，则需要重新从磁盘加载，机器的状态（如漏斗中的物品）以最后一次保存为准。

### 案例 2：穿过传送门时发生了什么？

穿传送门时，`PortalForcer` 向目标维度添加一张 `PORTAL` 类型 ticket：

```java
// 等效于：
addTicket(PORTAL, targetChunk, 3, targetBlockPos)
// level = 33 - 3 = 30 → ENTITY_TICKING
```

这张 ticket 的 `radius=3`，意味着目标传送门周围 3 区块距离都获得 level ≤ 33 的加载。它持有 300gt（15 秒）的过期时间——足够玩家穿过并站稳。15 秒后如果玩家没在附近，ticket 过期，区块卸载。

### 案例 3：`/forceload` 如何让区块永不卸载？

```java
// ChunkTicketManager.java
protected void setChunkForced(ChunkPos pos, boolean forced) {
    ChunkTicket<ChunkPos> chunkTicket = new ChunkTicket<>(ChunkTicketType.FORCED,
        ThreadedAnvilChunkStorage.field_29670, pos);  // field_29670 = ENTITY_TICKING
    if (forced) {
        this.addTicket(pos.toLong(), chunkTicket);
        this.simulationDistanceTracker.add(pos.toLong(), chunkTicket);
    } else {
        this.removeTicket(pos.toLong(), chunkTicket);
        this.simulationDistanceTracker.remove(pos.toLong(), chunkTicket);
    }
}
```

`FORCED` 类型的 ticket **没有过期时间**。它的 level 是 31（`ENTITY_TICKING`），直接加到目标区块。只要 `/forceload` 没有被手动移除，这张票就永远不消失——对应的区块永远在 `ENTITY_TICKING` 状态。


## 三个追踪器的分工总结

| 追踪器 | 控制的 ticket 类型 | 传播的内容 | 用途 |
|---|---|---|---|
| `TicketDistanceLevelPropagator` | **所有**非 PLAYER ticket | 每区块的综合最低 level | 驱动区块的加载/卸载决策 |
| `DistanceFromNearestPlayerTracker` | 无（仅记录距离值） | 区块到最近玩家的距离 | 控制客户端数据发送（视距） |
| `NearbyChunkTicketUpdater` | 自动添加/移除 PLAYER ticket | 视距内添加 level=31 ticket | 实现玩家周围区块加载 |
| `SimulationDistanceLevelPropagator` | 独立记录 ticket 并传播 | 独立的 level 值 | 决定是否执行方块/实体运算 |

四者协作的节奏：`tick()` 中依次 `updateLevels` → `tick` 所有变化的 `ChunkHolder`。

## [!ADVANCED] 源码分析

### ChunkHolder 的三种 Future

```java
// ChunkHolder.java - 三个 CompletableFuture
private volatile CompletableFuture<Either<WorldChunk, ChunkHolder.Unloaded>> accessibleFuture
    = UNLOADED_WORLD_CHUNK_FUTURE;
private volatile CompletableFuture<Either<WorldChunk, ChunkHolder.Unloaded>> tickingFuture
    = UNLOADED_WORLD_CHUNK_FUTURE;
private volatile CompletableFuture<Either<WorldChunk, ChunkHolder.Unloaded>> entityTickingFuture
    = UNLOADED_WORLD_CHUNK_FUTURE;
```

`UNLOADED_WORLD_CHUNK_FUTURE` 是一个已完成（completed）的 future，值为 `Either.right(Unloaded.INSTANCE)`，表示"未加载"。升级时，`chunkStorage.makeChunkAccessible`/`makeChunkTickable`/`makeChunkEntitiesTickable` 返回真正去加载的 future；降级时，`complete(UNLOADED_WORLD_CHUNK)` 把 future 重置回未加载状态。

### makeChunkTickable 与区块周边

```java
// ThreadedAnvilChunkStorage.java
public CompletableFuture<Either<WorldChunk, ChunkHolder.Unloaded>> makeChunkTickable(ChunkHolder holder) {
    // 确保周围 1 区块距离内的区块都达到 FULL
    CompletableFuture<Either<List<Chunk>, ChunkHolder.Unloaded>> completableFuture
        = this.getRegion(holder, 1, distance -> ChunkStatus.FULL);
    // 取中间的区块作为 WorldChunk
    return completableFuture.thenApplyAsync(
        chunks -> chunks.mapLeft(cs -> (WorldChunk) cs.get(cs.size() / 2)), ...)
        .thenApplyAsync(either -> either.ifLeft(chunk -> {
            chunk.runPostProcessing();           // 执行后处理
            this.world.disableTickSchedulers(chunk);  // 禁用旧 tick 调度器
        }), this.mainThreadExecutor);
}
```

注意 `getRegion` 的 `margin=1`：要使一个区块进入 ticking 状态，它周围 1 区块距离内的区块必须都达到 `FULL`。这是为了保证光照计算和方块更新的正确性。

### ServerWorld.tick 中的权限检查

`ServerWorld.tick` 中大量使用了 `shouldTick`、`shouldTickBlocks`、`shouldTickEntities` 来筛选需要运算的区块。这些方法最终都查询 `SimulationDistanceLevelPropagator` 的 level 表。
