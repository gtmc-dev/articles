假设你是Mojang的工程师，现在你遇到了一个问题：如果在主线程上一边运行世界生成一边还得处理游戏各项业务，游戏需要在主循环里每gt都轮询一下“要不要生成新区块？”然后如果要生成新区块，生成新区块的过程又会堵塞主线程，把后续业务全部卡死。

这个时候会有一个非常自然而然的想法：把世界生成部分从主线程踹出去，变成一个异步线程。但如果读者拥有一定的计算机科学基础，很容易意识到这是个相当危险的操作：这很有可能会导致竞态条件。也就是，两个线程试图同时修改一个区块，然后就会造成各种各样的bug。为了规避这个问题，Mojang决定加一个线程锁。区块必须完全生成完成才能被游戏主线程修改。因此，Mojang设计了区块的两种实现：准生成区块与已生成区块。

现在，我们已经知道区块有准生成和已生成两种形式，但是准生成区块是如何从无到有，一步一步变成已生成区块的呢？答案就藏在本节的第一个研究：区块生成状态中。

## 区块生成管线

区块生成状态具体指12个状态，按顺序的话包括：

0. 空区块，也就是区块生成的起点，不包括任何起始结构。
1. 结构起始，确定可能在区块中起始的结构。
2. 结构参照。用于生成跨区快结构。
3. 群系。确定生物群系。
4. 地形生成噪声。用于生成地形的大致轮廓与基岩层。
5. 地表。替换地表附近的方块。
6. 洞穴。生成洞穴与峡谷
7. 地物。生成地物，包括树木，紫水晶，矿石，地牢等。
8. 光照初始化。
9. 光照计算。
10. 生物生成。
11. 生成完成。在此阶段，准生成区块会准备被转化为已生成区块。

每个阶段都有一个对应的生成任务或加载任务（取决于是否从磁盘加载），定义了从上一个状态推进到当前状态需要执行的运算。

## 外圈依赖

在阅读上文时，部分读者可能会疑惑：如果无法确认一个区块周围的区块，如何确认一个区块自身的状态呢？比如，如果周围区块连群系都不确定，当前区块如何能够生成与周围地形连续的地形呢？因此，我们需要引入外圈依赖的概念。

外圈依赖指：一个区块要推进到某个区块状态，其周围一定距离内的区块至少要达到某个最低状态，这个距离由任务边距决定。

各个阶段的任务边距大致如下：

| 阶段 | 任务边距 | 说明 |
| ---------------------- | ---------- | ------------------------------ |
| 结构起始 | 0 | 结构的起始位置仅依赖本区块 |
| 结构参考 | 8 | 需要周围结构的参照信息 |
| 群系 | 8 | 生物群系插值需要周围噪声数据 |
| 地形生成噪声 | 8 | 地形生成需要周围生物群系信息 |
| 地表 | 8 | 地表构建需要周围噪声信息 |
| 洞穴 | 8 | 洞穴生成需要连通到周围区块 |
| 地物 | 8 | 地物（如大树）可能跨越区块边界 |
| 光照初始化 | 0 | 仅初始化本区块光照 |
| 光照计算 | 1 | 光照计算需要与邻块协调 |
| 生成完成 | 0 | 转换不需要外部信息 |

### 切比雪夫距离

任务边距使用的距离度量是切比雪夫距离。对于区块坐标 `(x₁, z₁)` 到 `(x₂, z₂)`：

$$\text{距离} = \max(|x_1 - x_2|, |z_1 - z_2|)$$

例如，`(0, 0)` 到 `(8, 0)` 的距离 = 8，到 `(8, 8)` 的距离也是 8。这意味着 `任务边距 = 8` 时，生成波及的是一个以目标区块为中心、边长为 `2×8+1 = 17` 的正方形区域。

### 生成不可达时的处理

当某个区块因为加载票的约束无法达到生成完成时，它的区块状态会停留在与"到最近准加载区块的距离"相匹配的阶段：

| 到最近准加载区块的距离 | 停留的区块状态 |
| ---------------------- | ----------- |
| 0 | 生成完成 |
| 1 | 地物 |
| 2 | 洞穴 |
| 3~10 | 结构起始 |
| 11 | 空区块 |

这意味着，1.20.1 中距离准加载区块正好 1 区块远的区块，只会生成到地物——洞穴有了、地物也有了，但光照是不完整的。只有当它周围区块吃到更强的加载票，级别足够低时，生成才会继续向后推进。

## 光照系统

光照系统是区块生成管线中的特殊环节。与其它状态不同，它在实际上不更改任何方块的布局，仅计算已生成的方块的亮度。光照计算由光照提供器统一管理，分为光照初始化和光照两个阶段进行。本节只介绍光照如何嵌入区块状态生成管线，其余内容会在后文提及。

### 光照初始化阶段

光照初始化的运作流程大致为：

1. 标记哪些子区块非空
2. 将每个非空子区块的光照系统计算状态设置为`false`，并告知光照阶段需要计算/重计算这一子区块的光照。
3. 这一阶段不会执行完整光照传播。只是告诉光照系统哪些子区块需要计算光照。

### 光照阶段

光照阶段执行完整的光照传播，确保目标区块及其相邻区块的亮度正确。我们在此处并不关心光照系统的具体运作方法。总之，光照传播是跨区块的，一个光源可能会影响周围多个区块的亮度。完成后，标记该区块的光照已就绪。

注意，完成光照时会要求周围8格的相邻区块必须至少同样完成光照阶段，否则边界光照会不正确。

另外，光照线程是异步执行的。

从磁盘加载旧区块时，即使上述两个阶段都已经完成了，游戏也会强制重新计算光照。

#### 光照票的自动管理

我们稍后会具体讨论其详细内容，这里只需要知道：当一个区块需要光照计算时，光照系统会自动给那个区块添加临时的光照票。这张票确保了在光照计算期间，目标区块及其相邻区块保持加载状态。这张加载票会在计算完成后自动过期，从而避免了光照计算到一半，相邻区块/当前区块被卸载的竞态条件。
