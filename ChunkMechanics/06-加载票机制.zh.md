前几章反复提到了"加载票"这个词。本章将它单独展开，从每一个 Ticket 的诞生到消亡，讲清楚"票"到底是什么、怎么用、怎么传播。

## 什么是加载票

加载票（Ticket）是一个用于标明**区块加载原因**的对象。它的核心数据结构非常简单：

```java
public class ChunkTicket<T> {
    private final ChunkTicketType<T> type;  // 什么原因
    private final int level;                // 多少等级
    private final T argument;              // 附加参数（如 ChunkPos）
    private long tickCreated;              // 创建于第几 tick
}
```

一张票回答三个问题：**为什么加载**（type）、**加载到什么程度**（level）、**加载哪里**（argument）。

## 加载票类型全表

1.20.1 中一共有 8 种加载票类型：

| 类型 | 参数类型 | 用途 | 典型过期时间 | 典型加载距离 |
|---|---|---|---|---|
| `START` | `Unit` | 服务端启动时加载出生点 | 不休眠 | 11（level=22） |
| `DRAGON` | `Unit` | 龙战期间加载末地主岛 | 不休眠 | 9（level=24） |
| `PLAYER` | `ChunkPos` | 玩家所在的区块 | 不休眠 | 由模拟距离决定 |
| `FORCED` | `ChunkPos` | `/forceload` 指令强加载 | 永不过期 | level=31 |
| `LIGHT` | `ChunkPos` | 需要计算光照的区块 | 根据光照任务 | 视需要 |
| `PORTAL` | `BlockPos` | 穿过传送门时加载目标维度 | 300 gt（15秒） | 3（level=30） |
| `POST_TELEPORT` | `Integer` | 实体传送后加载目标区块 | 5 gt | 0~1 |
| `UNKNOWN` | `ChunkPos` | 代码通过 `getChunk()` 获取区块时自动添加 | 1 gt | 0~1 |

### 各类型详解

**START**：`MinecraftServer.prepareStartRegion()` 在出生点周围以 `radius=11`（level=22）添加。这张票在服务端启动后立即生效，并在生成完成后一直存在——确保出生点区块永不卸载。

**DRAGON**：`EnderDragonFight.tick()` 在龙战期间以 `radius=9`（level=24）加载末地主岛。战斗结束后移除。

**PLAYER**：这是最常见的票。由 `NearbyChunkTicketUpdater` 自动管理——当玩家移动时，进入视距的区块获得 PLAYER 票，离开视距的区块失去。它不是"每个玩家一张票"，而是"每个在视距内的区块各一张 PLAYER 票"。

**FORCED**：`/forceload` 通过 `ChunkTicketManager.setChunkForced()` 添加，level 固定为 `ENTITY_TICKING`（31），永不过期。只有当手动执行 `/forceload remove` 时才被移除。

**LIGHT**：光照系统在需要计算某个区块的光照时添加。这是一张临时票——光照计算完成后自动过期。

**PORTAL**：实体穿过下界传送门时，`PortalForcer.getPortalRect()` 在目标维度添加。`radius=3` 意味着目标传送门周围 3 区块都被加载，level=30（强加载）。300 gt（15 秒）的宽限期确保实体有足够时间穿过并站稳。

**POST_TELEPORT**：`/tp` 等传送操作后添加。`radius` 通常为 0 或 1，5 gt 后过期——只保证传送落地的区块在短时间内可用。

**UNKNOWN**：当代码通过 `World.getChunk()` 等方式获取区块时自动添加。`radius=0`，1 gt 后过期。它的作用是**防止区块在获取后立即被卸载**——给了调用者至少 1 gt 的时间来完成对区块的操作。

## 票的添加与移除

### 添加票

```java
// ChunkTicketManager.java
public <T> void addTicket(ChunkTicketType<T> type, ChunkPos pos, int radius, T argument) {
    ChunkTicket<T> ticket = new ChunkTicket<>(type,
        ChunkLevels.getLevelFromType(ChunkLevelType.FULL) - radius, argument);
    // = new ChunkTicket<>(type, 33 - radius, argument)
    ...
}
```

`radius` 被转换为 `level = 33 - radius`。因此：
- `radius=0` → level=33（`FULL`）
- `radius=1` → level=32（`BLOCK_TICKING`）
- `radius=2` → level=31（`ENTITY_TICKING`）
- `radius=11` → level=22（远超强加载，足够覆盖出生点区域）

添加后，票被存入 `ticketsByPosition`——一个以 `long` 坐标索引的 `SortedArraySet<ChunkTicket>`。同一区块的所有票按 level 升序排列，`getLevel()` 返回集合中第一个（即 **level 最小的，也就是最"强"的**）票的 level。

### 移除票

移除票后，如果某区块的票集合变为空，该区块从 `ticketsByPosition` 中移除。然后 `distanceFromTicketTracker` 重新计算该区块的 level——当没有任何票时，level 变为 `INACCESSIBLE + 1`。

## 票的传播

一张票加到中心区块后，周围区块如何确定自己的加载等级？`TicketDistanceLevelPropagator` 负责这个计算。

传播规则严格遵循切比雪夫距离：

```text
对于中心区块 (cx, cz) 上的票，其 level = L：
周围区块 (x, z) 的 level = L + max(|x - cx|, |z - cz|)
```

即：每向外走一个区块（包括对角线），level +1。

例如，一张 level=31（强加载）的票加在 `(0, 0)`：

```
35  34  33  34  35      ← 向外 2 格 = level 33
34  33  32  33  34
33  32 [31] 32  33      ← 中心 = level 31
34  33  32  33  34
35  34  33  34  35
```

`TicketDistanceLevelPropagator` 继承自 `ChunkPosDistanceLevelPropagator`，使用经典的 level 传播算法——`propagateLevel` 向 8 个邻居广播，`recalculateLevel` 取所有邻居的 `min(level+1)`。

## 三个追踪器的分工

`ChunkTicketManager` 维护了四个追踪器，各自负责一种 level 的计算：

| 追踪器 | 负责的 ticket | 传播的粒度 | 用途 |
|---|---|---|---|
| `TicketDistanceLevelPropagator` | 所有非 PLAYER ticket | 每区块一个综合最低 level | 驱动 ChunkHolder 的加载/卸载 |
| `DistanceFromNearestPlayerTracker` | 玩家位置（不直接管理 ticket） | 每区块到最近玩家的距离 | 控制客户端数据发送（视距） |
| `NearbyChunkTicketUpdater` | 自动增删 PLAYER ticket | 视距内的区块被加 ticket | 实现玩家周围区块加载 |
| `SimulationDistanceLevelPropagator` | 独立记录并传播 level | 单独的 level 表 | 决定方块/实体运算的权限 |

## 票的过期与回收

`ChunkTicketManager.purge()` 每 tick 被调用一次，遍历所有票：

```java
protected void purge() {
    this.age++;
    for (entry : ticketsByPosition) {
        for (ticket : entry.getValue()) {
            if (ticket.isExpired(this.age)) {
                iterator.remove();  // 票过期，移除
                simulationDistanceTracker.remove(...);  // 同步从模拟距离表移除
            }
        }
        if (list became empty) { remove entry from ticketsByPosition; }
        if (any ticket removed) { distanceFromTicketTracker.updateLevel(...); }  // 重新计算 level
    }
}
```

过期的判定基于 `tickCreated` 和票类型：

- `POST_TELEPORT`：`age - tickCreated >= 5`
- `UNKNOWN`：`age - tickCreated >= 1`
- `PORTAL`：`age - tickCreated >= 300`
- `PLAYER`、`FORCED`、`START`、`DRAGON`：`isExpired()` 始终返回 `false`——不休眠

## 票系统不是计数器，而是等级传播器

一个常见的误解是把票系统理解为一个"引用计数器"——添加一张票就 +1，移除一张票就 -1，减到 0 就卸载。

事实远非如此。票系统的核心机制是**等级传播**：

1. 每张票有一个 **level**（不是 count）；
2. 同一区块的多张票取 **最低 level**（最强的优先）；
3. level 通过**距离传播**影响周围区块；
4. 最终每个区块接收到的是一个**综合 level**，这个 level 决定了它的 ChunkLevelType。

因此，两张 level=33 的票不等于一张 level=31 的票——它们各自的 level 独立参与 min 运算。而"加了两张票又删了一张"，剩余那张票的 level 仍然决定了最终结果——不存在"计数归零"的概念。

## 小结

- 8 种加载票类型覆盖了启动、玩家、传送门、指令、光照等各种加载原因。
- 票的核心属性是 level，同一区块取最低 level；level 通过切比雪夫距离向外传播。
- 票的过期时间因类型而异：`POST_TELEPORT`（5gt）到永不过期（`FORCED`）。
- 三个追踪器各自负责 level 的传播和计算，共同驱动 ChunkHolder 的状态变化。
- 票系统不是引用计数，而是等级传播系统——加一张 level=31 的票比加三张 level=33 的票更"强"。

### ChunkTicket 核心结构与过期判定

```java
// ChunkTicket.java
public final class ChunkTicket<T> implements Comparable<ChunkTicket<?>> {
    private final ChunkTicketType<T> type;
    private final int level;
    private final T argument;
    private long tickCreated;

    // 按 level 排序：level 越小越"前"
    public int compareTo(ChunkTicket<?> other) {
        int i = Integer.compare(this.level, other.level);
        if (i != 0) return i;
        // level 相同 → 按 type 的 identityHashCode 排
        int j = Integer.compare(System.identityHashCode(this.type), ...);
        return j != 0 ? j : this.type.getArgumentComparator().compare(this.argument, ...);
    }

    protected boolean isExpired(long currentTick) {
        long l = this.type.getExpiryTicks();
        return l != 0L && currentTick - this.tickCreated > l;
        // expiryTicks = 0 → 永不过期（START、DRAGON、PLAYER、FORCED）
    }
}
```

### level 传播算法

`ChunkPosDistanceLevelPropagator.propagateLevel` 向 8 个邻居传播：

```java
// ChunkPosDistanceLevelPropagator.java
protected void propagateLevel(long id, int level, boolean decrease) {
    ChunkPos chunkPos = new ChunkPos(id);
    for (int k = -1; k <= 1; k++) {
        for (int l = -1; l <= 1; l++) {
            long m = ChunkPos.toLong(chunkPos.x + k, chunkPos.z + l);
            if (m != id) this.propagateLevel(id, m, level, decrease);
        }
    }
}

// recalculateLevel：取 8 个邻居的最小 level+1
protected int recalculateLevel(long id, long excludedId, int maxLevel) {
    int i = maxLevel;
    for (int l = -1; l <= 1; l++) {
        for (int m = -1; m <= 1; m++) {
            long n = ChunkPos.toLong(j + l, k + m);
            if (n == id) n = ChunkPos.MARKER;
            if (n != excludedId) {
                int o = this.getPropagatedLevel(n, id, this.getLevel(n));
                if (i > o) i = o;
                if (i == 0) return i;
            }
        }
    }
    return i;
}

protected int getPropagatedLevel(long sourceId, long targetId, int level) {
    return sourceId == ChunkPos.MARKER
        ? this.getInitialLevel(targetId)    // 源点是中心 → 取初始 level
        : level + 1;                        // 邻居 → 起点 level + 1
}
```
