进入一个存档后，我们通常会把其中的一切统称为"这个世界"。但当你穿过下界传送门时，一件有趣的事情发生了：你仍然可以使用相同的坐标，那里却有完全不同的方块和实体。

显然，只知道坐标还不够。

## 一组坐标不能确定一个方块

假设我们说"坐标 `(0, 64, 0)` 上有一个石头"。这里其实少了一个条件：它位于哪个维度？

主世界的 `(0, 64, 0)`、下界的 `(0, 64, 0)` 和末地的 `(0, 64, 0)` 指向三个不同的地方。它们拥有相同的三个坐标数值，但分别属于三个不同的维度。

因此，要在游戏中确定一个方块，当且仅当同时给定：

1. 它所在的**维度**；
2. 它在该维度中的**坐标**。

两者缺一不可。缺少维度时，同一组坐标对应三个不同位置；缺少坐标时，维度只是一个没有空间位置的抽象环境。

在源码中，`BlockPos` 就是整数形式的 `x`、`y`、`z` 坐标；`World` 则表示这些坐标所属的维度——它的职责就是管理坐标之下的方块和实体。`World` 中预先定义了主世界、下界和末地的三个维度标记：

```java
World.OVERWORLD
World.NETHER
World.END
```

这三个常量的类型都是 `RegistryKey<World>`。它们不是三个额外的世界对象，而是用于说明"当前 `World` 属于哪个维度"的标记。

服务器使用一个以维度标记为索引的表保存所有 `ServerWorld`。创建存档时，它先创建主世界，再遍历维度注册表，为其他维度分别创建 `ServerWorld`。所以从代码角度看，一个存档可以包含多个维度；每个 `World` 对应其中一个维度的方块、区块和实体运行环境。

> [!TIP]
> 平时说"这个世界"时，它可能指整个存档，也可能只指当前维度。两种说法在日常交流中都很常见。为了避免混淆，本章将完整的一局游戏数据称为**存档**，将一个 `World` 对应的运行环境称为**维度**。

## 维度规定了什么

不同维度不只是拥有不同的方块。一个 `World` 还持有自己的维度类型、维度标记、区块管理器、边界、生物群系访问器和随机数生成器等内容。

维度类型进一步规定了这个维度的一些基本规则。它的每一项配置都是硬性的——不符合配置的操作（如在高度限制外放置方块）会直接被拒绝。具体包括：

- **最低可用高度**（`min_y`）；
- **维度的总高度**（`height`），由此得出上界 `topY = bottomY + height`（上界不含在范围内）；
- **是否拥有天空光照**；
- **是否拥有天花板**（影响亮度计算和结构生成）；
- **坐标缩放比例**（影响传送门的目的地计算）；
- **是否设置维度固定时间**（`fixed_time`，仅影响天体渲染角度，详见下文）。

在 1.20.1 的原版数据中，主世界的 `min_y` 为 `-64`，`height` 为 `384`。因此主世界能够放置方块的 Y 坐标范围是 `-64` 至 `319`（319 = -64 + 384 - 1）。下界和末地的 `min_y` 都是 `0`，`height` 都是 `256`，范围是 `0` 至 `255`。

高度限制的判定规则为：`y < bottomY` 或 `y >= topY` 时视为超出高度限制。注意上界不含在范围内——在 `topY` 高度上的操作已经非法。

## 分开保存，但并非全部独立

维度间的数据独立性分为两个层面：

**完全独立的数据**：每个维度的区块、方块、实体完全独立，保存在各自的目录下。`LevelStorage.Session#getWorldDirectory` 根据维度标记取得对应的保存目录。

**共享的数据**：以下属性由主世界统一定义，其余维度通过 `UnmodifiableLevelProperties` 封装来读取主世界的值：

- 游戏时间（`getTime()`）
- 游戏内时间（`getTimeOfDay()`）
- 天气状态（是否雷雨、雷雨剩余时间、晴天剩余时间）

不存在独立的"下界时间"或"末地天气"——一切对时间和天气的查询，最终都回到主世界属性。但注意：这并不意味着所有维度都必须和主世界共享时间。通过修改或替换 `UnmodifiableLevelProperties`，可以使特定维度拥有独立的时间流。

### 维度固定时间不是另一套计时器

维度类型中的 `fixed_time` 可以直译为**维度固定时间**。这个名字很容易让人误以为"该维度拥有一套停止不动的时间"。这里需要明确区分 `fixed_time` 影响的范围：

| 受影响 | 不受影响 |
|---|---|
| 天体渲染角度（太阳、月亮的位置） | 游戏时间（`getTime()`） |
| 环境黑暗程度（由此影响怪物生成的光照条件） | 计划刻执行 |
| 天空光照计算 | 实体和方块实体运算 |

`fixed_time` 的直接使用位置只有一处：`DimensionType#getSkyAngle`。这个方法计算天体角度时，会优先使用 `fixed_time`；没有设置它时，才使用维度读取到的 `timeOfDay`。

例如，下界的维度类型包含 `fixed_time: 18000`，末地包含 `fixed_time: 6000`。这里的数值会代替 `timeOfDay` 参与天体角度计算，但不会代替 `getTime()` 返回的游戏时间。

因此，本文统一称其为**维度固定时间**，并将其本质概括为：**"维度类型为天体角度计算指定的固定输入值，不参与游戏时间的推进，也不影响任何计时器驱动的游戏逻辑。"**

## 游戏如何根据坐标查找方块

虽然我们可以向 `World` 询问某组坐标对应的方块状态，但 `World` 并没有把所有坐标直接塞进一张无限大的表。

当调用 `World#getBlockState` 时，维度严格按以下三步完成查询：

1. 根据坐标中的 X、Z 数值计算区块坐标；
2. 取得对应的 `WorldChunk`；
3. 让区块返回该位置的方块状态。

如果坐标超出高度限制，第 1 步就会直接返回 `VOID_AIR`，不会尝试查找区块。

因此，维度的职责是"根据坐标找到对应的区块"，而区块的职责才是"从该位置的存储结构中取出方块状态"。这是一种严格的委托关系：`World` → `Chunk` → `ChunkSection` → `PalettedContainer<BlockState>`。下一篇将具体介绍区块。

## 客户端维度与服务端维度

`World` 中有一个 `isClient` 字段，用于区分当前维度对象属于客户端还是服务端。它的两个实现分别承担不同职责：

| | `ClientWorld` | `ServerWorld` |
|---|---|---|
| 职责 | 展示和预测 | 执行规则和保存结果 |
| 方块状态来源 | 服务端同步 | 区块存储（权威数据） |
| 实体运算 | 插值渲染 | 完整 AI 和运动计算 |

两者都能查询方块和实体，但服务端负责决定游戏中真正发生了什么；客户端接收同步结果并将它们展示给玩家。

这一区别能够解释一种常见现象：网络不稳定时，玩家有时会短暂看到一个方块已经被破坏，随后它又重新出现。客户端维度曾经认为方块发生了变化（因为玩家操作在本地产生了即时反馈），但最终仍要以服务端同步的状态为准——`BlockUpdateS2CPacket` 到来时，客户端会被迫纠正。

**核心规则**："我看见了什么"和"服务端记录了什么"可能短暂不一致，但游戏状态永远以服务端为准。

## 小结

- 确定一个方块，当且仅当同时给定维度和坐标，两者缺一不可。
- 源码中的一个 `World` 对应一个维度；一个存档包含多个 `World`。
- 维度类型规定了六项硬性规则：最低高度、总高度、天空光照、天花板、坐标缩放、维度固定时间。
- 区块数据各维度独立，但游戏时间和天气默认由主世界统一定义。
- `fixed_time` 仅影响天体角度计算，不停止任何计时器驱动的游戏逻辑。
- `World#getBlockState` 按"计算区块坐标 → 获取 WorldChunk → 返回 BlockState"三步完成查询。
- 客户端和服务端各有自己的维度对象，游戏状态以服务端为准。

## [!ADVANCED] 源码分析

### World 的核心结构

`World` 同时服务客户端和服务端，通过 `isClient` 字段区分：

```java
// World.java
public static final RegistryKey<World> OVERWORLD
    = RegistryKey.of(RegistryKeys.WORLD, new Identifier("overworld"));
public static final RegistryKey<World> NETHER
    = RegistryKey.of(RegistryKeys.WORLD, new Identifier("the_nether"));
public static final RegistryKey<World> END
    = RegistryKey.of(RegistryKeys.WORLD, new Identifier("the_end"));

public final boolean isClient;
private final RegistryKey<World> registryKey;

public boolean isClient() { return this.isClient; }
```

这三个常量是 `RegistryKey<World>` 类型，用来标识维度身份，不是三个世界对象实例。

### MinecraftServer.createWorlds：创建所有维度

服务端启动时，先创建主世界，再遍历维度注册表创建其余维度：

```java
// MinecraftServer.java
protected void createWorlds(WorldGenerationProgressListener worldGenerationProgressListener) {
    ServerWorldProperties serverWorldProperties = this.saveProperties.getMainWorldProperties();
    Registry<DimensionOptions> registry = ...;

    // 先创建主世界
    DimensionOptions dimensionOptions = registry.get(DimensionOptions.OVERWORLD);
    ServerWorld serverWorld = new ServerWorld(
        this, this.workerExecutor, this.session,
        serverWorldProperties,    // 使用主世界属性
        World.OVERWORLD,          // 注册键
        dimensionOptions,         // 维度选项
        ...
    );
    this.worlds.put(World.OVERWORLD, serverWorld);

    // 遍历注册表，创建其他维度
    for (Entry<RegistryKey<DimensionOptions>, DimensionOptions> entry : registry.getEntrySet()) {
        RegistryKey<DimensionOptions> registryKey = entry.getKey();
        if (registryKey != DimensionOptions.OVERWORLD) {
            RegistryKey<World> registryKey2 = RegistryKey.of(RegistryKeys.WORLD, registryKey.getValue());
            // 关键：非主世界维度使用 UnmodifiableLevelProperties
            UnmodifiableLevelProperties unmodifiable = new UnmodifiableLevelProperties(
                this.saveProperties, serverWorldProperties);
            ServerWorld serverWorld2 = new ServerWorld(
                this, this.workerExecutor, this.session,
                unmodifiable,           // ← 包装了主世界属性
                registryKey2,
                entry.getValue(), ...
            );
            this.worlds.put(registryKey2, serverWorld2);
        }
    }
}
```

注意：主世界以外的各维度在构造时传入的是 `UnmodifiableLevelProperties`，而非独立的属性对象。

### UnmodifiableLevelProperties：维度间的属性共享

```java
// UnmodifiableLevelProperties.java
public class UnmodifiableLevelProperties implements ServerWorldProperties {
    private final SaveProperties saveProperties;
    private final ServerWorldProperties worldProperties;  // 主世界的属性

    public UnmodifiableLevelProperties(SaveProperties saveProperties, ServerWorldProperties worldProperties) {
        this.saveProperties = saveProperties;
        this.worldProperties = worldProperties;
    }

    public long getTime() { return this.worldProperties.getTime(); }
    public long getTimeOfDay() { return this.worldProperties.getTimeOfDay(); }
    // 所有时间、天气相关的方法都转交给 worldProperties（主世界属性）
}
```

这里解释了为什么原版各维度共享游戏时间和天气：非主世界维度没有独立的 `ServerWorldProperties`，它们的所有时间、天气读取都委托给了主世界的属性对象。

### DimensionType.getSkyAngle：维度固定时间的真正作用

```java
// DimensionType.java
private final Optional<Long> fixedTime;

public float getSkyAngle(long time) {
    double d = MathHelper.fractionalPart(
        this.fixedTime.orElse(time) / 24000.0 - 0.25);
    double e = 0.5 - Math.cos(d * Math.PI) / 2.0;
    return (float) (d * 2.0 + e) / 3.0F;
}
```

`fixedTime.orElse(time)` —— 如果维度类型定义了 `fixed_time`，就用它代替传入的 `time`；否则正常使用维度读取到的游戏时间。注意这个方法只影响天体角度计算，不修改 `World#getTime()` 返回的游戏时间。

下界 `fixed_time: 18000` 和末地 `fixed_time: 6000` 意味着它们的天体角度始终对应午夜和黄昏，但计划刻、实体、方块实体仍按真实游戏时间运行。

### World#getBlockState：根据坐标查找方块

虽然 `World` 提供了 `getBlockState(BlockPos)` 接口，但它本身不直接存储方块数据：

```java
// World.java（简化逻辑）
public BlockState getBlockState(BlockPos pos) {
    if (this.isOutOfHeightLimit(pos)) return Blocks.VOID_AIR.getDefaultState();
    // 委托给 WorldChunk
    return this.getWorldChunk(pos).getBlockState(pos);
}
```

维度只是查找的入口，真正的方块数据由 `Chunk` → `ChunkSection` → `PalettedContainer<BlockState>` 层层委托获取。

### World.removeBlock：破坏方块时用流体替代

```java
// World.java
public boolean removeBlock(BlockPos pos, boolean move) {
    FluidState fluidState = this.getFluidState(pos);
    return this.setBlockState(pos, fluidState.getBlockState(),
        Block.NOTIFY_ALL | (move ? Block.MOVED : 0));
}
```

破坏含水方块后留下的水不是额外补放的，而是 `removeBlock` 先获取了当前位置的 `FluidState`，然后将对应的方块状态写入。这与正文所述一致。

### 客户端与服务端维度

```java
// World.java
public final boolean isClient;

// 两个重要实现：
// - net.minecraft.server.world.ServerWorld   （服务端）
// - net.minecraft.client.world.ClientWorld    （客户端）
```

客户端维度也有自己的 `getBlockState` 等查询方法，但它展示的是服务端同步过来的快照。当网络不稳定时，客户端的状态可能与服务端暂时不一致——`BlockUpdateS2CPacket` 就是服务端向客户端同步方块变化的数据包。
