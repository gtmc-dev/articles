# 维度与方块章节配图规格

本目录中的正式配图统一使用以下命名规则：

- 文件名使用小写 ASCII 与连字符（kebab-case）。
- 栅格图使用 `.png`；需要保留像素边缘时禁止 JPEG。
- 图中出现的源码类型使用 Yarn `1.20.1+build.10` 名称。
- 中文标签使用正文术语，首次出现时可以在括号中附英文。
- 普通流程图建议使用 16:9、1600×900；结构图可使用透明背景。
- 正文引用时必须提供能独立说明信息的中文 `alt` 文本。

## `save-dimension-chunk-structure.png`

用途：用于《重新认识维度》的“一组坐标不能确定一个方块”部分。

内容：

- 最外层是一个名为“存档”的容器。
- 容器内并列三个维度：主世界 `overworld`、下界 `the_nether`、末地 `the_end`。
- 每个维度下方各有独立的区块网格。
- 在三个维度中分别标出 `(0, 64, 0)`，三组坐标使用不同方块图标，强调坐标相同但维度不同。
- 从“存档属性”分别连接到三个维度，使用虚线表示时间等部分属性共享。
- 不绘制完整服务端 tick 流程。

建议 alt：

> 一个存档包含主世界、下界和末地三个维度，每个维度拥有独立区块；相同坐标在不同维度中指向不同方块。

## `chunk-coordinate-grid.png`

用途：用于《区块》的“从方块坐标到区块坐标”部分。

内容：

- 俯视一张跨越 X=0、Z=0 的 `48 × 48` 方块网格。
- 用粗线划分 `16 × 16` 区块。
- 标出区块 `(-1, -1)`、`(0, -1)`、`(-1, 0)`、`(0, 0)`。
- 特别标出方块 X=`-1`、`0`、`15`、`16` 四列。
- 每个示例同时显示方块坐标、区块坐标和区块内坐标。
- 负坐标区域必须清晰，避免只画正坐标。

建议 alt：

> 跨越坐标原点的区块网格，展示方块坐标 -1、0、15、16 对应的区块坐标与区块内坐标。

## `subchunk-structure.png`

用途：用于《区块》的“子区块”部分。

内容：

- 左侧画一个主世界区块的竖直柱体，水平尺寸标为 `16 × 16`，高度标为 384。
- 柱体从 Y=`-64` 到 Y=`319`。
- 将柱体切分为 24 个高度为 16 的子区块。
- 右侧放大其中一个子区块，标明 `16 × 16 × 16 = 4096` 组坐标。
- 用箭头展示“方块 Y → 子区块坐标 → 数组下标 → 子区块内 Y”的转换。
- 最底部示例应写明：方块 Y=`-64`，子区块 Y=`-4`，数组下标 `0`，子区块内 Y=`0`。

建议 alt：

> 主世界区块按高度划分为 24 个十六格高的子区块，并放大展示单个 16×16×16 子区块。

## `block-state-combinations.png`

用途：用于《方块与方块状态》的“属性和值”部分。

内容：

- 左侧为一个“橡木楼梯 Block”节点。
- 中间列出四个属性：`facing`、`half`、`shape`、`waterlogged`。
- 每个属性旁列出允许值的简化集合。
- 右侧展示四到六个具有明显差异的楼梯状态，包括朝向、上下半部、转角和含水。
- 用组合关系而非流程箭头连接，表达状态是属性值的组合。
- 页脚注明“状态集合在 StateManager 创建时枚举”。

建议 alt：

> 橡木楼梯的 facing、half、shape、waterlogged 属性组合成多个预先定义的方块状态。

## `block-change-pipeline.png`

用途：用于《方块的放置、改变与破坏》的共同入口部分。

内容：

- 主流程从左至右：
  1. 确定位置与新状态；
  2. `World#setBlockState`；
  3. `WorldChunk#setBlockState`；
  4. `ChunkSection#setBlockState`；
  5. 处理旧、新状态；
  6. 根据 flags 发送更新与同步。
- 从区块写入节点分出四条支线：高度图、光照、方块实体、需要保存。
- 从 flags 节点分出三条支线：监听者/客户端、NC 更新、PP 更新。
- 用不同颜色区分“数据写入”和“写入后的副作用”。
- 图中不要展开 NC、PP 的内部顺序，改用指向方块更新章节的标签。

建议 alt：

> 方块状态从坐标计算进入 World、WorldChunk 和 ChunkSection，写入后再更新高度图、光照、方块实体并按 flags 通知其他系统。
